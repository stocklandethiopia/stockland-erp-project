# Stockland ERP 16.1.58 Full Audit Follow-up

**Date:** 2026-10-11  
**Target release:** 16.1.57 corrective source, built through the isolated audit branch  
**Status at time of this historical note:** source-gate review in progress on PR #2

## What GitHub passed

- Original merge/code-analysis checks for PR #1 and CodeQL job matrices completed successfully. These results certify those CI jobs only, not the full ERP source profile or a live installation.
- The ERP package/source CI job passed complete PHP syntax lint, Composer validation/install, the targeted production-service PHPCS profile, PHPUnit regression suite (**7 tests / 13 assertions**) and deterministic application QA before the full-source PHPCS gate.
- Bundled static QA covers source contracts for the 49 business tables, role/REST permissions, import gates, CSS assets, payroll arithmetic and operational workflow expectations. The read-only integrity smoke test is synthetic/mocked (**6 assertions**) and is not a scan of a real database.

## Full-source PHPCS/WPCS finding reduction

The first full-source PHPCS inventory (run #69, artifact ID 11685408531) reported **84,218 errors + 6,089 warnings** across 75 PHP files. The updated fail-closed workflow ran PHPCBF before regression tests. Its run #70 inventory (artifact ID 11686931605) reported **2,777 errors + 1,942 warnings** across 75 PHP files, with only 2 reported fixable by PHPCBF. It then correctly failed at “Enforce zero full-source PHPCS/WPCS findings” instead of publishing a false green.

The leading residual categories in that report were:
- direct custom-table queries / no query caching (WordPressCS warnings; ERP uses direct SQL for row locks, ledger atomicity and exact branch stock; these still need architecture-aware review);
- SQL preparation and interpolated SQL identifiers (these need item-by-item review; Stockland_DB::table() and trusted $wpdb table identifiers must not be confused with arbitrary user input);
- documentation and style rules;
- custom ERP capabilities (now declared to WordPressCS in the full audit ruleset);
- CLI QA/test scripts intentionally mock WordPress globals and emit command-line output (now covered by PHP lint, PHPUnit and deterministic QA, but excluded from the deployable-runtime WPCS profile).

## Source fixes made on the isolated branch

1. Package workflow now triggers on pushes to main as well as audit branches and watches release packages and audit evidence in PR events.
2. The workflow applies PHPCBF to the full PHP tree before regression tests, persists mechanical changes only on audit branches, retains the separate production-service PHPCS gate, uploads full-source findings, and has a blocking full-runtime PHPCS/WPCS step. It is not allowed to report a successful package gate while that profile is failing.
3. Archive build normalizes timestamps and sorts paths before ZIP creation to make identical-source builds reproducible.
4. Fatal-request diagnostics sanitize REQUEST_URI and REQUEST_METHOD; query strings/nonces remain excluded from stored route diagnostics.
5. Physical-count workbook preview validates upload structure, upload error, sanitized file name/path and is_uploaded_file() before parsing.
6. The WPCS capability list recognizes the ERP’s registered stockland_* capabilities. The runtime coding-standard profile excludes tests/ and tools/qa/; these remain under whole-package syntax lint, PHPUnit and deterministic QA scripts.
