# Stockland ERP 16.1.66 — Finance & Procurement Authority Audit

**Status:** corrective source candidate; exact-release CI and live acceptance are pending.  
**Base snapshot:** `016706167874c3ef6233265a86f59f8e203da050`.  
**Release target:** in-place update; 49 business tables and schema markers remain unchanged (`16.1.1`, `16.1.15`, `16.1.3`).

## Defects found in source review

1. Finance/procurement queries used logical names as SQL identifier values after `%i`, instead of the physical prefixed table names from `Stockland_DB::table()`. This affected purchase-order status/receipt checks, receipt replay, PO line locking/receiving, customer lookups, expense idempotency, GL journal verification, invoice reads and payment allocation checks.
2. Some invoice/PO reconciliation queries supplied values in an order different from the SQL placeholders. The AP/AR payment allocation query supplied the invoice type where the second table identifier was required. These errors can cause failed queries or incorrect reconciliation behavior.
3. Expense authority was globally Owner-only, conflicting with the expressly amended operating SOP. Branch and Central Warehouse Managers had no usable location-specific final-decision flow; Warehouse Manager lacked the expense capability in the canonical role map.
4. The expense form allowed client-selected locations for corporate roles. That risks misattributing Management/Owner expenses to a branch. The updated backend ignores client-supplied branch IDs for corporate roles and stores no branch location for those expenses.
5. Branch/Warehouse Manager finance UI access could not be enabled by simply exposing the full accounting bootstrap because that response contains supplier/AP/AR data. A separate role-scoped UI path now reads only the expenses endpoint for those roles; Owner/Management receive a read-only expense report.

## Corrected authority contract

| Workflow | Entry | Final authority | Scope |
|---|---|---|---|
| Branch expense | Active Branch Manager | Active Branch Manager | Only that profile's assigned branch |
| Central Warehouse expense | Active Warehouse Manager | Active Warehouse Manager | Canonical Central Warehouse only |
| Management expense | Active Management profile | Posts as its own corporate expense | No branch attribution; visible for reporting |
| Owner expense | Active Owner profile | Posts as its own corporate expense | No branch attribution; visible for reporting |
| External product PO | Management creates and submits using existing stockable Product Master SKUs, quantities and unit costs | A different active Owner approves | Central Warehouse destination only |
| PO receiving | Warehouse Manager | Warehouse Manager records actual accepted quantities | Approved PO lines; accepted quantity alone posts inventory |
| Supplier invoice/AP | Management prepares after the required approved PO and posted receipt | Independent Owner decision | Matched invoice/receipt; no duplicate input-VAT posting |
| Customer invoice/AR and payments | Existing role/capability workflow | Existing role/capability workflow | Separate accounting stages; they must not gate PO creation |

The explicit user amendment permits a Branch Manager or Warehouse Manager to make the final decision on an expense they entered, provided the active ERP role and assigned location match. This is recorded as a same-actor decision in the existing audit chain; no other branch or corporate role can decide that location expense. Legacy PENDING rows created under the prior workflow are not rewritten; they remain visible in Owner/Management reports but are excluded from the new location-authority action queue unless the creator role matches the assigned authority, so they require controlled reconciliation rather than a misleading approval button. Management and Owner can review the expense report but cannot approve location expenses.
